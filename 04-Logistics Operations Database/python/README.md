# Python Pipeline — Logistics Operations Database

This folder contains the Python scripts used to inspect the raw data, clean it into master analytical tables, validate the SQL database, and run the logistic regression model for the maintenance analysis (Track C).

The pipeline is designed to be run in sequential order.

---

## Folder Structure

- **`analysis/`** — The 4 Python scripts used in the pipeline.

- **`outputs/`** — Text reports generated by the scripts, containing data profiles, cleaning logs, and model results.

---

## Setup & Requirements

The scripts rely on standard data science libraries. To run them, ensure you have the following installed:

`pip install pandas numpy scikit-learn statsmodels matplotlib`

*(Note: Make sure your working directory is `python/analysis/` when running the scripts, as they reference relative paths to the `data/` and `sql/` folders).*

---

## The Pipeline Steps

### 1. Data Inspection (`01_inspect.py`)

**Purpose:** Profiles the 16 raw CSV files to understand data types, missing values, and basic distributions before any transformations.

**Input:** `data/raw/*.csv`

**Output:** `outputs/01_inspect_report.txt`

**Action:** Run this first to validate that all source files are present and correctly formatted.

### 2. Data Cleaning (`02_clean_data.py`)

**Purpose:** Applies all cleaning rules (date parsing, type casting, handling missing values, deduplication) and merges the 16 raw tables into 3 analytical master files. 

**Input:** `data/raw/*.csv`

**Output:** 
- `data/processed/master_driver_clean.csv`
- `data/processed/master_trip_clean.csv`
- `data/processed/master_truck_month_clean.csv`
- `outputs/02_clean_report.txt`

**Action:** This is the most critical script. It builds the foundation for both the SQL database and the Power BI dashboard.

### 3. SQL Validation (`06_validate_sql.py`)

**Purpose:** Runs a series of programmatic sanity checks against the SQLite database to ensure the Python cleaning logic matches the SQL `load_data.py` logic. It checks row counts, null counts, and checksum totals.

**Input:** `sql/db/logistics.db`

**Output:** `outputs/06_validate_report.txt`

**Action:** Run this *after* you have run `sql/load_data.py` to ensure the database loaded correctly.

### 4. Track C Modeling (`07_track_c_model.py`)

**Purpose:** Fits the logistic regression model on the `truck_month` data to identify the drivers of a high-cost maintenance month. It calculates odds ratios, generates a calibration curve, and runs a what-if simulation.

**Input:** `data/processed/master_truck_month_clean.csv`

**Output:** `outputs/07_model_report.txt`

**Action:** Run this to see the statistical proof behind the dashboard's Track C findings (specifically the 12.5x odds ratio for preventive visits and the what-if simulation showing increased costs).

---

## Output Reports

The `outputs/` folder contains the text reports generated by these scripts:

- **`01_inspect_report.txt`** — Raw data profile.

- **`02_clean_report.txt`** — Summary of rows kept, dropped, and imputed during cleaning.

- **`06_validate_report.txt`** — SQL vs. Python consistency checks.

- **`07_model_report.txt`** — The full logistic regression output, including the counterintuitive finding that adding 10% more preventive visits increases cost by $387K.
